# 0001 — Локальный MCP-сервер из четырёх слоёв с выделенным COM-потоком

- Date: 2026-10-27
- Status: accepted
- Approved by: owner

## Context

Сервер должен управлять ЛИРОЙ через COM на компьютере пользователя, поддерживать несколько
версий ЛИРЫ, переживать модальные окна и долгие расчёты, а позже — работать как сетевой
сервер для нескольких пользователей. Решение определяет, как устроен весь код.

## Options

### Один процесс, четыре слоя: инструменты → сервисы → COM-поток → адаптер версии — chosen

- Advantages: транспорт (stdio, позже HTTP) меняется только в верхнем слое; различия
  версий собраны в адаптере; все вызовы COM идут из одного потока, как требует COM, и
  выполняются по очереди — одновременные запросы не мешают друг другу; тайм-ауты и поиск
  диалогов в одном месте.
- Limitations: одна ЛИРА на процесс сервера, команды выполняются последовательно. Предел —
  сетевой режим с параллельной работой нескольких пользователей: тогда понадобится
  несколько экземпляров ЛИРЫ или очередь заданий поверх сервиса.
- Cost and effort: умеренные — нужен свой COM-поток с очередью.
- Changing it later: легко добавлять транспорт и адаптеры; сложно уйти от одного потока COM.

### Простой сервер: инструменты напрямую вызывают COM

- Advantages: меньше кода на старте.
- Limitations: COM-объекты, созданные в одном потоке, нельзя вызывать из другого;
  асинхронный MCP-сервер вызывает обработчики из разных потоков — ошибки и зависания.
  Нет места для тайм-аутов и различий версий.
- Cost and effort: малые сейчас, большие при каждом расширении.
- Changing it later: дорого — переписывать все инструменты.

### Отдельный процесс-посредник для ЛИРЫ (сервер ↔ рабочий процесс)

- Advantages: зависание ЛИРЫ не роняет MCP-сервер; можно держать несколько ЛИР.
- Limitations: межпроцессный протокол, сложнее отладка и установка.
- Cost and effort: высокие.
- Changing it later: можно прийти к нему из выбранного варианта, вынеся COM-поток в процесс.

## Decision

Один процесс с четырьмя слоями и выделенным COM-потоком: самый простой вариант, который
закрывает требования PRODUCT.md (версии, диалоги, долгий расчёт) и не закрывает путь к
сетевому режиму.

## Consequences

- Все обращения к ЛИРЕ — только через очередь COM-потока; инструменты не трогают COM.
- Адаптер версии публикует список возможностей; по нему включаются инструменты.
- Включено предложение П6: агент видит модальные окна ЛИРЫ и может нажать кнопку.
- Журнал пишется в файл: в режиме stdio стандартный вывод занят протоколом MCP.
