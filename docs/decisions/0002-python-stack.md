# 0002 — Python, официальный MCP SDK и pywin32

- Date: 2026-10-27
- Status: accepted
- Approved by: owner

## Context

Нужен язык, на котором удобно вызывать COM ЛИРЫ, обрабатывать большие таблицы результатов
и выполнять скрипты агента (скрипт-инструмент из PRODUCT.md).

## Options

### Python 3.13 + MCP Python SDK 2.x + pywin32 — chosen

- Advantages: скрипт-инструмент выполняет Python-код агента без перевода; агенты лучше
  всего пишут на Python; pandas для результатов; pywin32 — зрелая библиотека COM с
  событиями и функциями окон Windows (для поиска диалогов); официальный SDK MCP.
- Limitations: COM вызывается динамически — ошибки в именах методов видны только при
  запуске; закрываем интеграционными тестами на реальной ЛИРЕ.
- Cost and effort: низкие; Python и uv уже установлены.
- Changing it later: дорого — переписывание сервера.

### C# / .NET 8 + MCP C# SDK

- Advantages: родная поддержка COM и типов из библиотеки типов; один исполняемый файл.
- Limitations: скрипт-инструменту пришлось бы компилировать C# на лету (Roslyn);
  обработка таблиц тяжелее, чем в pandas.
- Cost and effort: средние.
- Changing it later: дорого.

### TypeScript / Node

- Advantages: популярен для MCP-серверов.
- Limitations: COM доступен только через сторонний модуль winax — главный риск проекта.
- Cost and effort: высокие из-за COM.
- Changing it later: дорого.

## Decision

Python: лучшее сочетание с COM (pywin32), обработкой данных и выполнением скриптов агента.

## Consequences

- Зависимости в `.venv` через uv; установка у пользователей одной командой `uvx`.
- 64-битный Python: библиотека результатов `LiraResAPI.dll` загружается в процесс сервера,
  у ЛИРЫ 2024 есть её 64-битная версия.
- comtypes — запасной вариант, если pywin32 не справится с каким-либо интерфейсом.
