# Исследование: API ЛИРА-САПР

Дата: 2026-10-27. Источники: библиотеки типов установленной ЛИРА-САПР 2024 R2 (Update R2.3),
документация на rflira.ru и lira.land, релиз-ноты.

## Готовые MCP-серверы

Публичных MCP-серверов для ЛИРА-САПР / ЛИРА-САПФИР не найдено: ни на GitHub, ни в
каталогах MCP, ни у разработчика. Python-обёрток над API тоже не найдено.

## Какие программные интерфейсы есть

ЛИРА-САПР предоставляет три независимых COM-интерфейса. COM (Component Object Model) — механизм
Windows, через который одна программа вызывает объекты другой; из Python он доступен через
библиотеки `pywin32` или `comtypes`.

| Интерфейс | Где живёт | ProgID / библиотека типов | Назначение |
|---|---|---|---|
| ЛИРА-САПР API (ВИЗОР) | `Bin\x64\LiraSapr.exe`, отдельный процесс | `LiraSapr.Application` (2024); в 2025 — `LiraSapphire.Application` | Открыть/создать/сохранить модель, таблицы ввода, выделение, запуск расчёта, CSV-результаты, импорт файлов |
| RES API (результаты) | `Bin\x64\LiraResAPI.dll`, загружается в процесс клиента | `LiraSaprRes` | Чтение результатов расчёта: перемещения, усилия, РСУ, РСН, периоды колебаний, подобранная арматура, нагрузки на фрагмент, продавливание |
| САПФИР API | `Sapfir 2024\SAPFIR.tlb` | `Sapfir.Application.2024.0` | Архитектурная (BIM) модель: стены, плиты, колонны, этажи, оси; около 50 объектов автоматизации |

Полные выгрузки библиотек типов: [LiraSapr-2024R2.txt](typelib/LiraSapr-2024R2.txt),
[LiraResAPI-2024R2.txt](typelib/LiraResAPI-2024R2.txt).

## Что умеет ЛИРА-САПР API 2024 R2

- **Приложение**: `OpenDocument`, `CreateNewDocument`, `ImportFile` (импорт файла с шаблоном модели),
  `StartAnalysis` (асинхронно, события `AnalysisStarting/Finished/Stopped`),
  `StartAnalysisOnServer`, `StopAnalysis`, `DeleteResults`, `StartZip/StartUnzip` (архивы),
  `StartCmd` (любая команда меню по идентификатору), единицы измерения.
- **Документ**: `Save/SaveAs/Close`, выделение узлов и элементов, текущее загружение,
  собственный вес (`SetDeadWeightLoad`), модель грунта (`SetSoilModel`),
  генерация CSV-таблиц результатов при расчёте (`SetGenerateCsvTables`, около 80 видов таблиц).
- **Таблицы ввода** (чтение и запись двумерным массивом, `Apply` возвращает ошибки по строкам):
  координаты узлов, элементы (тип и узлы), связи, жёсткости и их назначение, коэффициенты постели C1/C2,
  жёсткие вставки, шарниры, объединение перемещений, локальные оси, монтажные стадии,
  РСН, загружения, массы, координационные оси, высотные отметки, конструктивные блоки,
  материалы конструирования.

## Пробелы и риски

- **Нет таблицы ввода нагрузок** на узлы и элементы. Возможные обходы: импорт текстового
  формата ЛИРА через `ImportFile`, таблица усилий для стержней, команды меню. Требует проверки.
- **РСУ** (расчётные сочетания усилий) отдельной таблицы ввода не имеют — проверить, как задавать.
- Многие методы могут показывать диалоги ("Messages from UI can be shown"); модальное окно
  остановит автоматизацию. Нужна стратегия: тайм-ауты, обнаружение зависания.
- ProgID и имя библиотеки типов сменились между 2024 и 2025 (`LiraSapr` → `LiraSapphire`).
- Нужна лицензия (ключ Guardant) и запущенный графический интерфейс ЛИРА; одна машина Windows.
- Документация методов — только описания внутри библиотеки типов; формат параметров таблиц
  нужно изучать, заполняя таблицы вручную в интерфейсе.

## Эксперимент T2 на живой ЛИРЕ 2024 R2.3 (2026-10-27)

Скрипты — папка `spikes/` (`t2_*.py`). Всё проверено из Python через pywin32.

**Работает:**

- Подключение `gencache.EnsureDispatch("LiraSapr.Application")` запускает `LiraSapr.exe` с
  окном. `CreateNewDocument` создаёт модель в папке Data ЛИРЫ; `SaveAs` переносит её
  в любую папку.
- Таблицы ввода: `CreateNewItem(тип, None, kLiraModelPart_All, имя, -1)` → `CastTo(...,
  "ILiraTable")`. `SetContents` принимает и текст с табуляциями, и список списков Python;
  `Apply()` возвращает `(успех, ошибки)`. `GetContents("")` на пустой таблице узлов или
  элементов падает с ошибкой — сначала проверять наличие данных.
- Форматы таблиц (по учебной модели): жёсткость — строка параметров сечения
  (`Ro:0 E:3e+006 B:60 H:40 … STD_END`); связи — номер узла и 6 флагов; загружения и
  РСН — таблицы с видом загружения текстом («Постоянное(П)»). Полная выгрузка —
  `spikes/out/*.tables.txt` (не в git).
- **Импорт текстового формата ЛИРЫ** `app.ImportFile(путь.txt, "")` создаёт новую модель с
  узлами, элементами, жёсткостями, связями, загружениями **и нагрузками** (документы 6 и 7).
- **Выгрузка в текстовый формат:** `app.StartCmd(5049)` («Создать текстовый файл» из меню)
  без диалога пишет `<папка Data ЛИРЫ>\<имя модели>.txt` в UTF-8; команда асинхронна —
  ждать появления файла. В файле есть нагрузки (6, 7) и настройки РСУ (8).
- **Расчёт:** `StartAnalysis(путь.lir)` возвращается сразу; события через
  `win32com.client.WithEvents` приходят при прокачке сообщений
  (`pythoncom.PumpWaitingMessages`): `AnalysisStarting(0)`, `(1001)`, `AnalysisFinished(0)`.
- **Результаты:** `Dispatch("{4F4546AE-AC54-48A2-9414-1B9EF6519A37}")` (LiraResultsAccess,
  ProgID нет) → запрос `kLiraRequest_LoadCaseForces`, `DocumentName` = имя модели без пути.
  Индексы: сечение с 1, загружение с 1, форма для статики = 1, история = 0. Единицы
  фиксированы: т, т·м.
- **Проверка числом:** рама 6×3 м, защемление, 10 т/м на ригель (40×60, E=3e6):
  M на концах ригеля −23,858 т·м, в пролёте 21,142, у основания стоек 11,575, N стоек 30 т.
  Ручной расчёт без сдвига: 24 / 21 / 12 / 30.

**Ограничения и риски:**

- Таблицы нагрузок в API нет. Новые модели — через генерацию текстового формата и
  `ImportFile`. Существующие модели — круг «выгрузка 5049 → правка → импорт» **с потерями**:
  виды загружений «Мгновенное» становятся «Особое» (меняются коэффициенты сочетаний),
  теряются конструктивные блоки. Нужна схема «импорт + восстановление таблиц из
  оригинала + сверка» (решается в T6).
- Результаты пишутся в папку Work ЛИРЫ под **именем модели**: модели с одинаковым именем
  из разных папок перезаписывают результаты друг друга.
- Выгрузка 5049 пишет в папку Data ЛИРЫ под именем модели — может перезаписать чужой
  файл с тем же именем.
- `SaveAs` с расширением `.txt` пишет двоичный `.lir`, а не текст.
- ЛИРА сама делает копии `*_Backup*.~lir` рядом с моделью при сохранении.
- Описания методов в библиотеке типов обрезаны до 255 символов.

## Находки T6 (2026-10-27)

- Папки ЛИРЫ — в реестре `HKCU\Software\LIRA SAPR\LIRA SAPR 2024\Directories`:
  `DataDirectory`, `TextDataDirectory`, `WorkDirectory`, `ResultDirectory`.
- Любое чтение таблицы (создание и удаление временной таблицы ввода) выставляет у модели
  флаг «изменена». Адаптер помнит модели, изменённые только своими чтениями, и не считает
  их изменёнными.
- При выгрузке ЛИРА дополняет строки значений нагрузок нулями до 4 значений.
- **Импорт текстового формата переключает модель на нормы сочетаний по умолчанию**: виды
  загружений («Мгновенное(М)» → «Особое ( Ps)») и РСН меняются, и записью строк в таблицы
  `LoadCases`/`DCL` это не исправить — ЛИРА переводит значения в словарь своих норм.
  Поэтому правка нагрузок существующих моделей работает только для моделей с нормами по
  умолчанию; для остальных сервер отказывается и оставляет модель нетронутой.
- COM-объекты нельзя держать в циклических ссылках и в трассировках исключений, которые
  уходят из COM-потока: сборщик мусора освободит их в другом потоке
  (`0x800401f0 CO_E_NOTINITIALIZED`).

## Находки T7 (2026-10-27)

- После окончания расчёта ЛИРА **закрывает документ** модели; для правки модель нужно
  открыть снова.
- Протокол расчёта — `<Work>/<имя>_01.<имя>` (UTF-8). Чистый расчёт заканчивается
  «Расчет успешно завершен», расчёт с проблемами — «Расчет завершен» и строки
  «ВНИМАНИЕ!!!» (например, геометрическая изменяемость). Код события
  `AnalysisFinished` в обоих случаях 0 — судить о проблемах можно только по протоколу.
- Во время расчёта ЛИРА пишет `<Data>/<имя>.txt` — текстовую копию модели.

## История API по версиям

| Версия | Что известно |
|---|---|
| 2021 R1 | API впервые объявлено ("технология API"); IronPython-ноды в САПФИР-Генераторе |
| 2022 R2 Update 3 | Добавлены импорт файлов и генерация результатов в CSV |
| 2024 R1 | Новые таблицы ввода: оси, высотные отметки, конструктивные блоки, материалы |
| 2025 | Расширены создание/корректировка модели и доступ к результатам, плагины |
| 2026 | Вышла; изменения API не изучены |

Вывод: ЛИРА 2021 даёт только таблицы ввода без импорта и CSV; полноценный цикл
"создать → рассчитать → выгрузить" складывается начиная с 2022 R2 U3, а с удобными таблицами
осей и материалов — с 2024 R1.
